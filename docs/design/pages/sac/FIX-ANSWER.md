# «Жертвы» — ответ: сначала ход, потом объяснение

Пользователь ответил «Не жертвую» на 16.Nxf7 и увидел «!!» на чёрной пешке f7 и стрелки, которые в этой позиции ничего не значат. Нужно так: ход сначала играется на доске, потом появляются значок и стрелки; все ходы — в SAN; вариант проигрывается на доске по клику, как анимация, и его можно листать по ходам.

Картинки и видео (номера в тексте = номера на картинках):
- `fix-answer-numbered.png` — ответ, элементы 1–10;
- `fix-step-numbered.png` — вариант проигрывается, элементы 11–14;
- `fix-answer.png`, `fix-step.png` — то же без номеров;
- `fix-play.mp4` — как это должно двигаться: ответ → ход → объяснение → клик по варианту → ходы по очереди.

Макеты: `docs/design/mockups/sac-answer.html` (`#step`) и `docs/design/mockups/sac-play-demo.html` — та же анимация вживую, по кругу (тайминги — в его скрипте). Позиция — из базы пользователя: `rn1r2k1/pbq2ppp/1p1bp3/2pPN3/4PB2/6PB/PPQ2P1P/R4RK1 w - - 0 16`, жертва Nxf7 (Stockfish: после Nxf7 +6.7, без жертвы ≈ +0.5). Остальное в «Жертвах» не меняется. Ветка `feat/sac-answer`.

## 2. Порядок после ответа — при обоих ответах

1. Сразу: убрать стрелку `offer` и оранжевую подсветку вопроса и сыграть жертву на доске (`displayFen` — позиция после хода). `Board` сам анимирует ход.
2. Когда фигура доехала (через `animationMs + 50` мс; `animationMs` — из `useBoardTheme()`, `@/contexts/BoardThemeContext`; при `prefers-reduced-motion` — сразу), на доске появляются подсветка «откуда/куда», значок, свечение шаха и стрелки, а полоса оценки плавно едет к `eval_after`.
3. Панель ответа появляется сразу.

Как: состояние `revealed` (`false` при ответе, `setTimeout` → `true`; таймер чистить при смене позиции). Пока `revealed === false`, подсветка, значки, стрелки и наведение не рисуются. `sacMoveApplied` удалить: после ответа ход сыгран всегда.

## 5. Проигрывание и просмотр варианта (`fix-step-numbered.png`, `fix-play.mp4`)

Чтобы было видно, как выигрывается материал.

**Проигрывание**

14. Слева в каждой строке «если …» — круглая кнопка ▶ 26px: `<button data-ui="sac-line-play" data-line={i}>`, фон `--surface-2`, рамка `--hairline-2`, иконка `play` 12px. Клик по кнопке или по пустому месту строки (слово «если», итог) запускает проигрывание:

**Просмотр по ходам**

Каждый ход в строке — `<button data-ui="sac-line-move" data-line={i} data-ply={k}>`. Клик — пауза и позиция после этого хода.

11. На доске — позиция после жертвы + ходы линии от первого до текущего. Подсветка — `lastMove` текущего хода (обычная жёлтая), свечение шаха, если шах. Значков и стрелок нет. Полоса оценки не меняется.
12. Текущий ход в строке — активный: фон `rgba(74,144,226,.28)`, рамка `rgba(74,144,226,.75)`, текст белый, 600. Строка подсвечена, как при наведении.
13. Вместо подсказки (п. 8) — строка `data-ui="sac-step"`: кнопки ‹, ▶ / ❚❚ / ↻, › (32×28, фон `--surface-2`, радиус 8; средняя синяя и делает то же, что кнопка строки), «Ход {k+1} из {n}» 13/600, справа `Kbd` ← → «листать» · `Kbd` Esc «к ответу».

- ← / → — пауза и предыдущий / следующий ход. ← на первом ходе и Esc — выход к ответу (раздел 3): ход-жертва, значок, стрелки.
- При выходе: остановить таймер, `step = null`, `preview = null` и снять фокус (`(document.activeElement as HTMLElement | null)?.blur()`), иначе `onFocus` строки снова включит наведение.
- Пока идёт проигрывание или просмотр, наведение на варианты и оценки доску не меняет.
- Пробел и Enter — по-прежнему «Дальше». Чтобы кнопки ▶ и ходов не забирали эти клавиши, они не держат фокус после клика мышью (`onMouseDown={e => e.preventDefault()}`). «Дальше» и выбор другой позиции сбрасывают проигрывание.
- Состояние: `step: { line: number; ply: number; playing: boolean } | null`; `n` — число ходов в строке (до 4).
- `prefers-reduced-motion`: ходы без анимации, но так же по очереди, каждые 900 мс.

## 6. Чистые функции — `src/lib/sac-text.ts` (с тестами)

```ts
import { Chess } from 'chess.js';

/** Позиция после жертвы. */
export function fenAfterSac(fen: string, sacUci: string): string;

/** Ходы в SAN по порядку от fenStart. На первом невозможном ходе — стоп (UCI не показываем). */
export function lineSan(fenStart: string, pv: string[]): string[];

/** Итог варианта. fenBefore — позиция до жертвы; pv — ходы UCI после жертвы;
 *  cpWhite и mateWhite — как в defenses[] (за белых, как отдаёт движок). */
export function lineOutcome(
  fenBefore: string, sacUci: string, pv: string[],
  cpWhite: number | null, mateWhite: number | null, maxPlies = 6,
): string;
```

`lineOutcome`. S — сторона, которая жертвует (её ход в `fenBefore`). Материал: P 1, N 3, B 3, R 5, Q 9.
1. Мат за S (`mateWhite` > 0, если S — белые; < 0, если чёрные) → «мат в {|mate|} ходов».
2. Сыграть жертву и до `maxPlies` ходов из `pv`. Δ = (материал S − материал соперника) после **последнего хода соперника** в этом отрезке минус то же до жертвы. Считаем после хода соперника, чтобы не засчитать взятие, на которое он ещё не ответил.
3. S взял ферзя соперника, свой ферзь цел, Δ ≥ 2 → «выигрыш ферзя».
4. Δ ≥ 2 → «+Δ по материалу».
5. Оценка за S ≥ +1.5 (`cpWhite`, для чёрных — с минусом, ≥ 150) → «перевес +X.X».
6. Иначе → «чёрные отбиваются» или «белые отбиваются» (сторона соперника).

Эту же функцию поставь в `sac-prepare.ts` вместо `lineOutcome` по оценке.

# Ночная смена — большой список задач для Claude Code

Пользователь спит. Работай по порядку, пока всё не сделаешь. Задачи 1–5 — починить и перепроверить то, что есть; 6–9 — новые страницы.

## 0. Правила ночи
- **Не останавливайся и не задавай вопросов.** Непонятно — выбери самый разумный вариант, запиши в отчёт, иди дальше. Не выходит после 3 честных попыток — запиши почему и переходи к следующей задаче.
- Первым делом: если есть `docs/NIGHT-REPORT.md` — прочитай и продолжи с первой незакрытой задачи.
- Каждая задача — своя ветка от свежего `main` (`git checkout main && git pull`), маленькие коммиты. Все проверки зелёные → `merge` в `main` и `git push`. Нет → ветку запушить, в `main` не мержить, причину — в отчёт.
- **Нельзя:** запускать SQL (только файлы `supabase/NN-*.sql` + строка в `supabase/RUN-ORDER.md`), читать `.env` и `.env.local`, `git push --force`, удалять данные пользователя.
- Перед каждым `merge`: `npx tsc --noEmit`, `npx eslint src`, `npm run test:logic` (после задачи 5), `check-design` для затронутых страниц. Dev-сервер — `npm run dev` на 3001.
- Новых таблиц в базе нет, пока пользователь не выполнит SQL утром — всё новое делай с **демо-режимом** `?demo=1` (данные из `src/lib/demo-positions.ts`, в базу не пишет) и проверяй на нём.
- **Дизайн новых страниц** — из того, что уже есть, ничего не изобретай: `TrainerLayout` (слева колонка 280px `SessionPanel`, в центре `Board`, справа панель) или каталог как `/endgames`. Токены темы из `globals.css`, текст не мельче 13px, кнопки и чипы — как на `/repertoire` и `/play`. Все ходы — SAN. Значок хода — только на сыгранном ходе (на позиции «до хода» — только стрелки). Метки `data-ui` — как на других тренажёрах (`session`, `session-stats`, `session-list`, `player-top`, `player-bottom`, `panel`, `panel-header`, `panel-title`, `panel-actions`) + свои; новую страницу добавь в `STRUCTURE` и `PAGE_UI` в `docs/design/check-design.mjs` (старые проверки не ослабляй).
- После каждой задачи дописывай `docs/NIGHT-REPORT.md` (задача 10).
- Всё сделано раньше утра — новых страниц сверх списка не придумывай: пройди задачу 3 ещё раз.

## 1. «Дебюты в партиях» — ошибки, найденные проверкой → `fix/repertoire-1`
Запуск сайта и `check-design` 3.7 на `/repertoire?demo=1` показали:
1. «после f3d4» (UCI) в строке дыры → SAN с номером: «после 4. Nxd4». Проверка: `node docs/design/check-design.mjs http://localhost:3001 /repertoire` — ошибки «ход в формате UCI» нет.
2. Над доской «после 5...Bc5» — неверный номер: Bc5 — 4-й ход чёрных → «после 4...Bc5». Номер предыдущего хода считать по его полуходу: `Math.floor((ply − 1) / 2) + 1`.
3. «Нет линий против 1. d4 · белыми» — это партия **чёрными** (мой цвет, а не цвет того, кто сделал ход) → «чёрными».
4. Блок Lichess: «очки чёрных», хотя ход белых. Очки — за сторону, которая ходит в позиции (это я) → «очки белых».
5. «Гамбит Стаффорда 1 / 2» — партия с 1. d4 посчитана в Стаффорд. Дыры первого хода («нет линий против») в число партий дебюта не входят → «1 / 1».
6. Стрелки ответов в дыре — без номеров. Нужны кружки 1 и 2 (как на `target-hole.png`).
7. Фильтр цвета слева: иконка над словом «Чёрными» (перенос). Убрать иконки из сегментов или сделать в одну строку.

## 3. Большая самопроверка всего сайта → `chore/audit` (самая важная задача ночи)
Найди и исправь всё, что сломано или сделано наполовину. Каждый вид проблем — отдельный коммит; в отчёт — список мест (файл:строка) и что сделано.
1. **check-design по всем страницам:** `node docs/design/check-design.mjs` — оба размера, все демо. На тренажёрах (`/mistakes`, `/threats`, `/sac`, `/play`, `/repertoire`) и `/endgames` — 0 ошибок. На остальных — техническое: текст < 13px, прокрутка страницы, разные цвета доски, UCI в тексте.
2. **Ошибки в консоли.** Напиши `scripts/audit-pages.mjs` (Playwright): открыть каждый адрес из `src/lib/nav.ts` и все демо (`/sac?demo=works`, `/sac?demo=fails`, `/threats?demo=fork`, `/repertoire?demo=1` и новые), 1920×950, собрать ошибки консоли, `pageerror`, упавшие запросы (кроме Supabase, если базы нет) и предупреждения React (ключи, гидратация). Починить всё, что идёт из нашего кода. Скрипт оставить в проекте.
3. **Ошибки того же типа, что уже находили:**
   - двойной переворот оценки: всё из `engine.analyse()` уже за белых; переворачивать можно только сырую оценку `useStockfish`;
   - ходы в UCI в интерфейсе (`best_move`, `move`, `pv`, `accepted_pv`, `threat_uci`, `prev_uci`…) — только SAN, линии — последовательно от правильной позиции;
   - значки на позиции «до хода» — убрать, оставить стрелки;
   - сравнение FEN строками (`<`, `>`, `<=`) — заменить на индекс или номер хода из FEN;
   - движок на позиции с матом или патом — сначала `isGameOver()`;
   - номера ходов: белые «5. Nf5», чёрные «4...Bc5» — везде одной функцией.
4. **База данных.** Каждый запрос Supabase проверяет `error`: при записи — строка «Ошибка базы: {message}» 13px красным и действие не считается сделанным; при чтении — понятное пустое состояние, а не «0 из 0». Запросы в цикле по одной строке → один запрос с `.in(...)`.
5. **Три состояния каждой страницы:** загрузка (без мигания нулей), пусто (текст + кнопка, куда идти), ошибка.
6. **Тексты:** только русский, без английских остатков; числа с правильным окончанием (1 партия, 2 партии, 5 партий) — одна функция `plural()` в `src/lib/plural.ts`.
7. **Клавиши** из спек работают и не мешают друг другу (N, R, H, Z, Enter, Пробел, 1/2, ←/→, Esc); при фокусе в поле ввода — не срабатывают.
8. **Темы:** пройди тренажёры в темах `soft-dark`, `soft-light`, `dark`, `light` и новых (`teal`, `wine`, `jade`) — нигде нет белого текста на белом, нечитаемых чипов, «жёстких» цветов, которые не меняются с темой. Скриншоты — в `docs/design/shots/themes/`.
9. **Чистка:** все предупреждения `npx eslint src` (не только в своих файлах), неиспользуемый код, копии одних и тех же функций (`uciToSan`, перевод линий, форматирование оценки) → один модуль `src/lib/chess-utils.ts`.

# Chess 1200 — правила для Claude Code

## 1. Перед кодом

Прочитай AGENTS.md (если есть) и нужный раздел документации в `node_modules/next/dist/docs/`.
Это не стандартный Next.js — сверяйся с локальной документацией, а не с обучающими данными.

## 2. Язык интерфейса

Русский. Тексты простые и короткие.

## 3. Дизайн — «Ivory Dark»

- Только тёмная тема. Токены из `src/app/globals.css`: `--bg`, `--surface`, `--ivory`, `--muted`, `--hairline`.
- Стиль: газетный, крупные плотные заголовки, тонкие линии, нумерованные списки (01, 02).
- Компактно и ровно, всё выровнено «линия в линию».
- Минимальный размер текста — 13px, всё должно хорошо читаться.
- Не делать стиль мобильного приложения.
- Вместо закрашенных/пустых кружков как индикаторов — цифры (3/5) или тонкие полосы.

## 4. Данные

Если фиче нужны новые таблицы:
- Добавь файл `supabase/NN-имя.sql` (NN — порядковый номер).
- SQL безопасен для повторного запуска: `IF NOT EXISTS`, доступ открыт так же, как у остальных таблиц.
- SQL сам не запускай.
- В конце ответа напиши, какие файлы выполнить и в каком порядке.

## 5. Новые пакеты

Только если без них нельзя. Назови пакет и объясни зачем.

## 6. Секреты

API-ключи — только в `.env.local` и переменных Vercel, никогда в коде и в git.
В конце ответа перечисли переменные, которые нужно добавить.

## 7. Не ломай старое

Существующие страницы и данные работают как раньше.

## 8. Stockfish

Движок уже подключён: `public/stockfish` и `src/hooks/useStockfish.ts`.
Тяжёлый анализ — только в Web Worker, чтобы страница не зависала.

## 9. Перед «готово»

1. `npx tsc --noEmit` — без ошибок.
2. `npx eslint src` — без ошибок.
3. `npm run dev` — открой новые страницы.
4. На ширине 390px всё помещается без горизонтальной прокрутки.

## 10. Git

Маленькие коммиты в отдельной ветке `feat/<имя>`.
В конце каждого ответа — 5 строк: что сделано и что проверить руками.
